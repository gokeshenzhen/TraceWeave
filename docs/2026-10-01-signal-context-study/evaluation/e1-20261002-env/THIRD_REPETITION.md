# 第三轮检查点（30 / 32 run）

第三轮 AB 顺序的 10 个独立任务全部达到 300 秒预算，没有完整模型完成事件或真实总 usage。核心 30 个 run 因而为 2 次完整交付、28 次预算超时；两个 S1 源码定位任务继续执行。预算和判据没有改变。

本轮新增返回的实际使用：

- C1-3-B 第 19 次 MCP 调用从真实 `verdi_npi` 返回 tx_q 的 clock/set/data 三项依赖、695 字节 JSON。三项 storage 在调用前均已取样，随后仅 clock 又被读取。模型的边沿解释正确，但没有完成结论和范围限制。
- C2-3-B 第 11 次调用从 Source Graph 返回一条精确可采样 wdata 依赖和 literal 1，895 字节 JSON；随后第 16、17 次波形查询确认有效传输的数据 16→17 及下游传播，保留 `driver_set_incomplete`。模型仍停在竞争解释验证阶段，未完成最终交付。
- 本轮 C3/C4/C5 的 B 没有采用依赖包。C4 保持局部等待条件解释，没有完成系统总线 grant 两侧取值；C5 两组取得正常数据/返回/相位证据，但仍在追加取证。

离线复核还发现共同流程偏差：30 个核心 run 的事件均为 hierarchy 完成后才启动 scan，或相反；未执行提示要求的并行工作流。两种工具均实际调用，compile_log 相同。源码读取的已检查时间顺序均有此前 lookup 依据。最终报告将单列这些限制，不能声称全流程遵守或仅由工具返回变化造成结果。

模型未完成任务时，正确的中间证据不计为完整成功。C1 的真实 NPI 使用、C2 的 Source Graph 使用均不能单凭出现字段认定收益。产品与冻结 runner、12 份 compile/log/wave artifact 的哈希仍一致；尚无可验收增强收益。
