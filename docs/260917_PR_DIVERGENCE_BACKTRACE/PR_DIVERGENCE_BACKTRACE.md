# PR 提案：首次差异与有界驱动回溯联动

状态：实施中。按文档、M1、M2、M3 分阶段验证并分别提交；本文中的验收要求不表示对应功能已经交付。

建议 PR 标题：`feat(debug): connect waveform divergence to bounded driver backtrace`

## 1. 问题与目标

当前 `diff_first_divergence` 可以找到指定两个波形信号在窗口内首次出现已知值不等的时刻，并注册游标。之后，调用者仍需自行确认编译上下文、查询驱动、选择上游信号，再反复读取波形。

本 PR 将这些步骤连接成可审查的证据链：

```text
指定 A/B 信号及比较窗口
  → 确认差异与比较覆盖范围
  → 分别解析两侧驱动、数据依赖和控制依赖
  → 确定每一侧实际需要检查的观察/采样时刻
  → 比较有明确对应关系的上游信号
  → 在预算内继续，或返回候选位置、证据缺口与下一步
```

目标是减少手工工具接力和无关上游展开。工具输出事实、候选和边界；不把最早观察到的差异、结构连通或单个活跃分支直接命名为根因。

典型行为：输出出现差异后，如果对应数据输入在相关采样点已经不同，继续调查该输入；如果分支选择不同，优先调查控制来源；如果完整的相关输入、控制及历史状态一致而输出不同，报告当前逻辑为候选并给出支持与限制。

## 2. 实现范围与交付方式

按 M1、M2、M3 顺序实现。三个里程碑均属于本提案的验收范围，可以分批评审；只完成 M1 时，不得宣称已实现自动差异回溯。

| 里程碑 | 必须交付 |
| --- | --- |
| M1：比较与工具接力 | 补齐比较覆盖语义；差异结果生成可执行或明确缺少前提的下一步；正确绑定 A/B 上下文 |
| M2：单步驱动证据 | NPI 与 Source Graph 均实现单步依赖、分支条件和时间证据；支持限定范围的组合逻辑与同步寄存器 |
| M3：有界自动回溯 | 新增 `trace_divergence`，组合比较和单步证据，输出有限证据图、候选、停止原因及资源回执 |

本 PR 的动态语义支持范围：

- 直接连接、静态位选、常量、连接表达式及可完整提取依赖的无延迟组合赋值。
- 有明确分支极性的 `if/else`；条件求值仅支持第 7 节定义的子集。
- 单一可识别时钟边沿的同步寄存器，含支持子集内的同步复位、使能和保持。
- 同一设计的不同运行，以及具有显式信号映射的同次/跨设计比较。
- 不满足动态语义条件的后端或结构仍可返回结构事实，但必须停止或标注为未确认候选。

以下不属于本 PR：

- 全设计自动枚举和差异排序；无界扇入扫描。
- 自动推断两次运行的周期偏移、流水线延迟、事务对应关系或设计等价性。
- 完整 SystemVerilog 求值器、仿真事件调度器、任意过程语句解释执行。
- 跨时钟域、异步复位事件、锁存器、任意延迟赋值、动态索引和 `force/release` 的自动因果展开。
- 波形格式迁移、重新仿真、界面开发、额外公开的通用表达式工具。

这些边界必须出现在实际结果中，而不是只写在文档中。

## 4. 不可破坏的约束

1. `diff_first_divergence` 的原有必选参数、默认已知值比较策略和原有字段继续可用。新增字段采用有默认值的加法式扩展。
2. 普通 diff 只读波形、生成后续动作；不在一次 diff 中隐式构建网表、提交 LSF 作业或查询 NPI。
3. 自动回溯由显式调用 `trace_divergence` 启动。保留现有后端优先级、能力降级和取消语义。
4. A/B 地位默认对称。调用者可以标注参考侧，但标注本身不证明另一侧错误。
5. 一侧一个明确的编译/层次/后端产物身份。不能把 A 的层次、KDB 或文件版本用于 B。
6. 返回的结构事实来自一致的后端及产物。任何后端切换或产物扩展均按第 10 节重启，不拼接不一致的半条链。
7. 波形缺失、X/Z、条件未知、映射不明、时序不明或资源截断都不是“没有问题”。
8. 保持 FSDB 进程全局锁、VCD 路径锁和双路径稳定锁序。连接关系查询、源文件读取与调度等待不得持有波形锁。
9. 不增加依赖安装、隐式全设计预加载、客户端配置修改或模拟器执行。

## 5. M1：比较结果与下一步合同

### 5.1 比较语义

`diverged` 保留原义：是否观察到两个可比较的已知值不等。`diverged=false` 单独不能解释为相等证明。

为 `DiffFirstDivergenceResult` 增加以下字段，具体 Pydantic 类型在 `src/schemas.py` 定义：

| 字段 | 含义 |
| --- | --- |
| `comparison_status` | `different` / `equal` / `inconclusive` |
| `coverage_status` | `complete` / `partial` / `none`，表示请求的比较范围实际检查程度 |
| `earliest_difference_proven` | 是否已排除窗口起点至已发现差异之间更早的未检查差异；不是全设计首次错误证明 |
| `coverage_gaps` | 固定原因码及必要的时间/侧别信息 |
| `next_actions` | 下述专用动作列表，默认空列表 |

规则：

- 只有请求有效范围完整可比较且未发现差异时，才能返回 `comparison_status=equal`。
- 已发现差异但扫描不完整时，仍保留差异事实，同时报告覆盖缺口。若更早的共同时间前缀已经完整检查，可以证明该对信号在该窗口内的最早差异；无法证明时将 `earliest_difference_proven` 设为 false。
- 默认维持已知值比较。X/Z 或不可读值不自动判成相等，也不静默更换为四态精确比较；没有已知差异且存在影响结论的未知区间时返回 inconclusive。
- 正确填充现有 `missing_a` / `missing_b`。区分无此信号、无初始值、空窗口、读取失败和过短 dump。
- 默认以两份波形有效记录范围的交集比较，并返回实际窗口及被排除的尾部；交集之外不能宣称一致。
- 相同时间戳上的所有记录按各自文件顺序消费完，再比较该时刻的最终可观测值，避免将中间更新误报为差异。
- 上述同刻合并指原始物理时间相同。亚 ps 记录转换成整数 ps 后的碰撞不能当成同刻；解析器未提供精确时间时报告精度缺口，不证明完整一致或最早差异。截断流的最后一个时间组若未证明完整，也不能提供该时刻的最终值或向后延续其值。
- 同宽信号按规范化位向量比较，保留位宽与 X/Z 信息。位宽不一致时报告不可比较，不进行隐式符号扩展、截断或整数强转。
- 消费 parser 的 transition 截断标记和独立 `predecessor`。取消异常必须穿透，不能转换成未知值或读取失败。

该阶段可修复导致虚假首次差异或虚假一致的比较问题，但必须为行为变化提供独立预期结果的回归测试，并更新工具说明。

### 5.2 加法式输入

为 diff 新增可选 `context_a`、`context_b`，仅供构造后续调用，每个对象包含：

```json
{
  "compile_log": "/work/run_a/compile.log",
  "simulator": "vcs",
  "supplementary_compile_logs": [],
  "top_hint": "tb"
}
```

`compile_log` 在提供该对象时必填；其他字段沿用现有语义。原有 `wave_path_a/b`、`signal_a/b` 保持不变。省略 context 不妨碍 diff。

不得仅凭“最近一次 `get_sim_paths` 或 `build_tb_hierarchy`”自动填入两侧 context。只有已验证波形归属和编译快照的精确匹配才可复用；否则将缺失前提返回调用者。

### 5.3 专用后续动作

新增专用 `DivergenceNextAction`，不改变握手等工具现有 `NextAction` 的含义。

| 字段 | 要求 |
| --- | --- |
| `side` | `a` / `b` / `both` |
| `tool` | 已注册工具名 |
| `arguments` | 可转交该工具的参数，禁止将时间参数塞给不接受时间的 driver 工具 |
| `reason` | 稳定原因码 |
| `status` | `ready` / `needs_context` / `needs_prerequisite` |
| `missing_fields` | 未提供的字段名；不能使用看似真实的占位路径 |
| `prerequisite_calls` | 已有参数足够时，给出准确的前置调用及依赖关系 |
| `evidence` | 差异时刻、游标、侧别等调查锚点，与工具参数分开 |

发现差异时，为两侧分别给出 `explain_signal_driver` 动作。已有完整编译上下文且对应 hierarchy 当前可用时，示例：

```json
{
  "side": "a",
  "tool": "explain_signal_driver",
  "arguments": {
    "wave_path": "/work/run_a/waves.vcd",
    "signal_path": "tb.dut.result",
    "compile_log": "/work/run_a/compile.log",
    "simulator": "vcs",
    "recursive": false
  },
  "reason": "inspect_divergent_signal_driver",
  "status": "ready",
  "missing_fields": [],
  "prerequisite_calls": [],
  "evidence": {
    "time_ps": 125000,
    "cursor_name": "div_example"
  }
}
```

执行规则：

- 缺 context 时，保留已知 wave/signal 参数，标为 needs_context；不能假装可直接运行。
- hierarchy 缺失或过期时，标为 needs_prerequisite，并给出对应 `build_tb_hierarchy` 与 `scan_structural_risks`。两者在同一 compile log 上并行执行；拆分日志的补充参数按目标工具实际合同传递。
- 不在 diff 内执行这些前置步骤。普通无差异结果不推荐根因回溯；inconclusive 可以返回解决缺失数据的动作，但原因不能写成“已发现差异”。
- 两侧完全相同的请求可以去重，但必须保留两侧关联。
- 补充日志等字段只能传给明确接受它们的工具。不能为了让 action 可执行而默默丢弃编译身份所需信息。
- ready 动作必须携带可在执行时重新验证的精确编译/层次身份。现有 driver 调度同时补齐该绑定；同一主日志配不同补充日志时不得采用最近一次上下文。该要求属于 M1，不推迟到 M3。

在 `server.py` 的 diff worker 返回、波形锁释放后，根据结果和已缓存的精确上下文组装动作；不得从 worker 写入调度会话状态。

## 6. M3 的公开入口：`trace_divergence`

M2 是该工具的内部证据能力，不另加一个功能重复的公开工具。M3 的最小调用形状如下：

```json
{
  "side_a": {
    "wave_path": "/work/run_a/waves.vcd",
    "signal_path": "tb.dut.result",
    "compile_log": "/work/run_a/compile.log",
    "simulator": "vcs"
  },
  "side_b": {
    "wave_path": "/work/run_b/waves.vcd",
    "signal_path": "tb.dut.result",
    "compile_log": "/work/run_b/compile.log",
    "simulator": "vcs"
  },
  "start_time_ps": "100ns",
  "end_time_ps": "200ns",
  "reference_side": "unspecified",
  "comparison": {"mode": "event"},
  "signal_pairs": [],
  "scope_pairs": [{"a": "tb.dut", "b": "tb.dut"}],
  "limits": {
    "max_depth": 8,
    "max_nodes": 128,
    "max_branches": 16,
    "timeout_sec": 30
  }
}
```

`side_a/b` 的 wave、signal、compile_log 必填；另外允许 simulator、top_hint、supplementary_compile_logs。两侧可以使用相同波形或编译产物，但必须经过身份验证后才能共享上下文。

`start_time_ps/end_time_ps` 复用现有 TimeSpec。`end_time_ps=-1` 保留为记录末尾的哨兵。`reference_side` 为 `unspecified/a/b`，只表达调用者角色，不参与真假裁决。

新工具自行验证双侧前提，不能只依赖当前单一 `_session_state` 的布尔状态。缺前提时返回分侧的结构化阻塞结果和准确下一步，不覆盖另一侧已经解析的上下文。

根节点差异在本次调用内重新检查。已有游标可以用于限定窗口，但不能把旧游标中的 value/metadata 当成未经验证的当前差异事实。

### 6.1 信号映射

- 根信号由 `side_a.signal_path` 与 `side_b.signal_path` 明确配对。
- 相同不可变设计身份下，可以对经过实际查验的相同完整路径自动配对上游信号。
- 不同设计身份时，调用者通过 `signal_pairs: [{"a": "...", "b": "..."}]` 或 `scope_pairs: [{"a": "tb.left", "b": "tb.right"}]` 明确给出对应意图。
- scope 映射按完整层次段前缀替换，随后在两侧分别确认真实声明、位选及位宽；不能用字符串后缀、同 basename 或相同 module 名猜测对应关系。
- 根路径即使相同，也不隐含所有上游都等价。scope 映射只是名称对应，不是语义等价证明。
- 映射必须一一对应；显式精确信号映射优先。重叠 scope、多义匹配、非法位选及冲突映射须在相关展开前拒绝或停止，不能任取一个。
- 未配对的候选作为 frontier 返回 `mapping_missing`，保留其已知结构证据。

### 6.2 比较采样模式

- `event`：沿物理时间比较，与 diff 默认模式一致。
- `clock`：额外要求 `clock_a`、`clock_b`、`edge=posedge/negedge`、`sample_offset_ps>=0`。先确认两侧窗口内的相应边沿时刻一致，再按共同边沿及偏移取值。
- 两个时钟的周期、相位或边沿数不匹配时，返回 `clock_alignment_unproven`。不静默取 A 的时间轴替 B 定义周期，也不自动退回 event 模式。
- 根节点的采样偏移是观察策略，不是寄存器输入采样语义。不能用正偏移代替触发边沿之前的值。
- 时钟模式仅说明采样点上是否存在差异；不能据此排除周期内瞬态。结果须携带模式、边沿和偏移。
- 没有有效共同采样点、时钟含不确定跳变或时钟 transition 截断时，不能返回 clean。

## 7. M2：驱动、条件与时间证据

### 7.1 单步内部合同

引入独立的内部单步观察结构，至少包括：

- 驱动/赋值标识、来源位置、真实后端及产物引用。
- 目标位范围、数据依赖、控制依赖、常量连接、依赖完整性。
- 组合、同步时序或不支持的边界类型。
- 查询时刻、触发边沿、输入采样语义、实际取值及其时间依据。
- 每条候选分支的条件、条件值、`true/false/unknown/unsupported` 状态。
- 是否能够证明候选集合完整、位覆盖完整、驱动唯一。
- 无法继续时的固定原因码。

M2 从现有后端准备/查询路径取得这些事实。`ExplainDriverResult` 只在确有需要时增加可选证据字段，不改变现有 structural driver 的含义，不要求所有后端伪装成具备动态能力。

扩展内部 IR 时同步处理 worker 序列化、反序列化、语义版本和缓存身份。旧内存/磁盘产物缺少动态字段时，只能作为明确缺少该能力的结构产物或缓存 miss；不能用默认值把旧产物升级成完整动态证据。

NPI 与 Source Graph 都是第一版动态语义的必选实现路径。默认沿用普通 connectivity/X-trace 工具的路由：可信且可用的 NPI 优先；NPI 不可用、查询失败或不能支持本次单步查询时，明确记录原因并降级到有界 Source Graph，最后才是 Legacy Static。有效的 NPI 结果不需要 Source Graph 复核。显式 `TRACEWEAVE_CONNECTIVITY_ROUTE=source_graph` 继续遵循现有策略，但正常使用不要求设置该变量。不得以尚未实现 NPI 适配为由将首版所有 NPI 节点统一标为 unavailable。

两种后端投影到相同的内部单步合同，共用四态条件求值、波形采样和图遍历。NPI 使用真实的 cell/port 类型、引脚连接、mux 条件标注和触发极性，必要时使用同一 KDB 的 Language Model；不能将完整扇入边界集合伪装成逐级路径。未 dump 的 NPI 内部生成节点应有界展开为真实声明、常量和支持的表达式。API 文本必须通过限定语法解析，禁止 eval。local 与 LSF 都复用现有执行策略；扩展单步查询时同步扩展 LSF 请求/结果协议。

后端查询失败与波形证据不足分别处理：X/Z、缺 dump、映射缺失、预算耗尽和用户取消均不能通过更换后端抹去。部分正向 NPI 事实保留现有完整性限制；不完整负面结果不能终止搜索。实际后端切换按第 10 节整图重启，并保持总预算。回归必须分别验证真实 NPI 动态证据、Source Graph 动态证据、NPI 优先、故障降级和取消不降级。

### 7.2 条件表示与求值

新增内部结构化条件表示；不能 `eval()` RTL 文本，也不能把现有 `guard` 字符串当成可信表达式。

首版条件子集：

- 单比特信号及布尔常量。
- 逻辑非、逻辑与、逻辑或。
- 固定位宽信号/静态位选与已知常量的 `==`、`!=` 比较；明确操作数位宽和 signedness，不能猜测隐式转换。
- 上述条件构成的嵌套 `if/else`，包含否定分支及优先关系。

至少以四态位值和未知状态求值：未知值不能按 Python truthiness 变成 false。支持 `0 && X`、`1 || X` 等可确定情形；缺失、未 dump、不可表达的操作数必须留下独立缺口。

不支持的函数调用、动态索引、特殊 case 匹配、过程内临时变量推导等返回 unsupported；可以继续展示结构依赖，但不能裁掉候选分支。

求值的两层结果要分开：

1. 条件能否确定，以及哪些分支可能执行。
2. 被选赋值是否足以解释目标值及目标位范围。

条件成立不自动证明该赋值是唯一驱动。多个可能驱动、驱动枚举截断、语句优先级未建模、局部位覆盖不完整时，保留歧义。

### 7.3 时序采样

同步寄存器的回溯节点不是一个无时间的信号名。

- 查询时刻 `t_obs`：输出差异被观察到的时刻。
- 触发时刻 `t_edge`：不晚于观察时刻、且由真实时钟和已识别过程触发信息支持的相应边沿。
- 输入取值 `before(t_edge)`：严格早于触发边沿的已知值；保留实际 predecessor 时间。
- 输出取值：明确表示触发边沿之后的可观测值或指定观察点。

必须遵守：

1. 识别 `always_ff @(posedge/negedge ...)` 和语义相同的普通 `always` 写法。多个不受支持的事件、异步复位或无法辨识的 clock 表达式停止为 `temporal_context_unavailable`。
2. 用同步复位、使能等控制在 `before(t_edge)` 的取值判断动作。两侧使能不同，优先报告控制差异；两侧都保持，继续检查上一状态，不能把当前 D 当成该 Q 的来源。
3. 不能用输出最近一次变化推定最近一次赋值。寄存器可能重复写入相同值，也可能保持多个周期。
4. 不使用 `t_edge-1ps` 模拟前一瞬间；通过有序 transition 和 predecessor 查严格前值。
5. FSDB tag 转 ps 可能合并亚 ps 记录；若无法确定严格前值或边沿内次序，返回 `sampling_order_unresolved`，不能暗称掌握了 delta/NBA 顺序。受限场景需要解析层补充可证明的精度/顺序证据后才可继续。
   此限制同样适用于 VCD 和整数 ps：严格前值不天然等于寄存器实际采样值。同刻输入/控制变化时，只有已验证的非阻塞同钟语义等证据能够证明采样关系才可继续，否则停止；TB 在同刻依次修改 D 和时钟的场景不能误判为本地逻辑候选。
6. 两侧输入采样时刻分别记录，并验证对应关系。跨不明时钟域、缺少前一边沿或超出请求历史窗口时停止，不自行向全仿真范围扩展。
7. 访问去重至少包含侧别设计身份、信号位范围、时间与采样相位。反馈寄存器在更早周期的同一信号不能被误判为组合环。

不要求本 PR 重放所有仿真调度区域。在已支持且可证明的语义子集外，明确停止即为正确行为。

## 8. M3：有界回溯算法

1. 解析并冻结 A/B 输入身份、时间窗口、映射、预算。验证两侧各自的层次前提。
2. 复用比较核心检查根信号。无差异且完整则返回 no_difference；未证实差异且覆盖不足则返回 inconclusive，不启动无依据的网表搜索。
3. 将已验证的差异对加入 frontier；节点携带两侧观察值、观察时刻、位范围和比较覆盖。
4. 在波形锁外查询该对信号的驱动及依赖。首先做单步查询，不用一次递归查询跳过需要验证的中间逻辑；确有端口穿越需要时，保留原始 hop 证据和完整性。
5. 根据结构化条件和时序合同选择相关采样点，批量读取候选数据、控制和历史状态。读完立即释放波形锁。
6. 对可配对、可比较的依赖生成证据边；有差异的依赖进入待检查队列。未知/未映射依赖留在 frontier，不能被过滤成正常分支。
7. 条件可证明为不执行时，可排除相应数据分支；无法证明时保留。一般算术或逻辑依赖不等于已证明传播，必须区分 `structural_candidate` 与具有值/位映射支持的传播证据。
8. 若完整相关输入、控制、初始/历史状态在对应采样点一致但输出不同，产生 `local_logic_candidate`，附带已排除项与限制。任何关键缺口均阻止此类排除性结论。
9. 达到输入/TB、常量、未支持语义、缺失波形、映射边界或预算时，记录停止原因和下一步。不得以“没有更多查询结果”证明找到了根因。
10. 返回证据图和候选摘要。候选排序可以使用经过验证的较早差异、与根节点的连接证据及完整性；时间更早本身不建立因果边。

图表示使用 `nodes` 和 `edges`，节点/边只存一次；不要在每个队列项复制完整路径。共享上游保留所有关联边，以节点 ID 引用共享证据。

必须保留的竞争解释包括：上游输入已不同、当前逻辑/控制产生差异，以及参考侧或映射不成立。已核实与未核实的两侧证据分别呈现。

## 9. 新工具输出合同

`TraceDivergenceResult` 至少包含：

| 字段 | 合同 |
| --- | --- |
| `status` | `complete` / `partial` / `blocked` / `no_difference` / `inconclusive` |
| `comparison` | 根节点比较结果、采样模式及最早差异是否已证明 |
| `contexts` | 两侧编译/波形身份回执和 backend_status，不复制整个 hierarchy |
| `nodes`、`edges` | 有界证据图，每个节点分别记录 A/B 事实与时刻 |
| `findings` | 候选类型、位置、支持事实、竞争解释和未检查项 |
| `frontier` | 未能展开或需要人工映射的具体节点及原因 |
| `coverage` | 已执行的检查、缺口、截断及已用/有效预算 |
| `next_actions` | 按第 5 节表达的后续动作 |
| `cursor` | 根差异游标；无已验证差异时为 null |
| `operation_metrics` | 数值聚合及固定标签 |

状态含义：

- complete 仅表示所声明、支持范围内的相关候选均得到处理，且不存在影响该范围结论的证据缺口；不表示整个设计已证明正确或根因唯一。
- partial 表示已有正向证据，但仍有缺口、未支持边界或预算 frontier。
- blocked 表示未能满足必要的编译/层次/执行前提。
- no_difference 只能来自完整可比较范围；未知或缺数据时使用 inconclusive。
- 用户取消继续使用现有取消通道，不伪装成正常 partial 返回。

固定停止原因至少覆盖：

`input_boundary`、`testbench_driven`、`constant_source`、`mapping_missing`、`mapping_ambiguous`、`signal_not_dumped`、`value_unknown`、`guard_unresolved`、`dynamic_evidence_unavailable`、`temporal_context_unavailable`、`sampling_order_unresolved`、`history_window_exhausted`、`clock_alignment_unproven`、`driver_set_incomplete`、`multiple_driver_candidates`、`transition_data_truncated`、`budget_exhausted`、`compile_context_changed`、`waveform_changed`。

新字段禁止把 TB consumer alias 重新包装成驱动。现有 `testbench_driven`、`cross_check`、`traversal`、`claim_semantics` 和后端排除项必须传播到相关节点。

游标只在最终可返回的根差异结果中注册一次；内部逐节点比较不注册游标。保持游标为进程内状态，不引入隐式“当前游标”。

## 10. 上下文、后端和缓存一致性

- 每个请求捕获两侧不可变上下文；按 compile log、补充日志顺序、simulator、top、内容快照验证身份。不能通过轮流修改全局当前 hierarchy 来实现双侧切换。
- 编译输入由调用者或已验证的发现结果绑定到对应波形。若旧运行对应的源码已被覆盖，且没有可验证的旧产物，必须返回前提缺口；不能用当前源码解释旧波形并声称版本已确认。
- 复用现有缓存键、新鲜度检查、单飞、按需 scope 扩展和资源准入。源文件变化时要求重新构建对应层次，不能继续使用旧事实。
- 两侧拥有各自可验证的后端和产物；允许两侧实际 backend 不同，但能力与置信边界必须分侧报告，不能替弱侧补造事实。
- 一侧发生后端回退或 Source Graph 产物扩展时，撤销依赖该轮结构事实的证据图，并从原始信号对重启。第一版优先采用整图重启，避免留下跨侧关联到旧节点的边。
- 重启受同一个总时间/工作预算约束，不能每轮重新获得完整预算。
- 不将新构建产物和旧产物的边混在同一侧最终链中。纯波形读缓存仅在文件身份、窗口和采样语义完全相同时可复用。
- 波形至少以 canonical path、文件 stat 身份及现有 parser 新鲜度机制校验。调用期间文件被替换或改变时，返回明确失效；不自动重开并把两次运行混在一个结果中。
- 跨调用不持久化回溯图；本 PR 复用已有产物缓存，不引入新的磁盘扫描或设计常驻服务。

## 11. 锁、取消和资源预算

初始公开默认值为 max_depth=8、max_nodes=128、max_branches=16、timeout_sec=30。硬上限建议分别为 32、1024、64、120；实现时集中放在配置中，并通过实测检查默认值是否合理。超上限输入返回验证错误，不默默改成无限制。

深度以根信号对为 0，每次跨越结构或历史状态依赖加 1；节点预算计入完整展开和停止的节点。`max_branches` 是每个节点允许展开的依赖对上限，超过的候选仍需计数并在 frontier 摘要说明。总节点上限约束整张图；重复访问通过身份键去重，不能靠把结果截短掩盖超预算搜索。

另设内部有界预算，覆盖总 transition 数、暂存波形字节、工作队列及 Source Graph 重启次数。初始建议：总 transition 计数上限 1,000,000、新增缓存 32 MiB、最多 3 次产物重启；达到时返回具体预算名称。已有 parser/native 单次容量限制继续生效，不能用这些数字声称 native 调用可被中途强制打断。

- 波形读取沿用 `_run_in_wave_thread`。双波形锁按现有稳定顺序获取；两个 FSDB 路径仍共享一个进程全局锁。
- 连接关系查询和条件/图计算不占用波形锁。Static/Source Graph 使用可取消 worker；NPI/LSF 保持已验证的执行路径。
- 不共享正在改变的 NPI loaded-design 状态来同时执行 A/B 查询。需要切换设计时串行且验证所查询设计身份。
- 在队列弹出、依赖展开、transition 遍历、缓存读取和产物重启前后设置取消检查。
- 单个等待者取消不终止其他等待者共享的构建；最后一个等待者取消才停止共享任务。取消不得触发后端降级。
- 超时预算包含排队、锁等待、后端准备与查询。不可中断的 native 调用返回后再兑现取消/超时，回执报告有效超时和实际耗时。
- 优先按同一节点/时钟组批量读取并尽快释放缓存；不要让所有已访问节点各自保留完整 transition 列表。
- 指标只允许耗时、数量、字节、缓存命中和固定阶段/原因。不得把路径、信号名、值、scope、映射表或指纹写入 operation metrics/telemetry。

## 13. 验收测试矩阵

测试的预期值来自独立的设计/时序说明和手工可核对的波形表，不能调用被测实现生成预期结果。源代码和测试夹具均在本仓库独立编写。

| 场景 | 必须证明的行为 |
| --- | --- |
| 旧 diff 调用 | 不传新参数仍可用，原字段及游标合同兼容 |
| 窗口起点已不同 | 正确报告窗口起点，不虚构更早时刻 |
| 同时间多次更新 | 最终值相等不产生中间态假差异；真正差异仍能发现 |
| 缺信号/全 X/缺初值/空窗口 | 不输出完整一致结论，原因准确 |
| transition 截断 | 已知差异可保留，未检查部分不能称 clean |
| 两份 dump 长度不同 | 清楚报告共同窗口和未比较尾部 |
| 等价值表示/不同位宽 | 规范化后比较；不隐式改变位宽语义 |
| A/B 对换 | 差异事实对称、侧别和值交换；不固定把 B 当错误侧 |
| 两侧不同编译日志但同名层次 | 始终落到各自源文件和产物，不能使用最后一个全局上下文 |
| 同一主日志、不同补充日志及交错动作 | M1 与 M3 均验证准确身份，不能请求 A 却返回 B |
| 同波形不同实例 | 显式映射可用；相似名字不产生自动错误映射 |
| M1 缺 context/hierarchy | 动作状态和前置调用真实，不输出不可执行的 ready |
| 无差异/不确定差异 | 不隐式触发 NPI、LSF 或 Source Graph 构建 |
| 组合数据差异 | 上游差异有结构与取值支持；无关变化不被称为根因 |
| mux 控制不同 | 检查两侧控制与所选数据分支，不能只沿一侧所选路径排除另一侧 |
| guard 为 X 或不支持 | 保留多个可能分支，报告条件缺口 |
| `if/else` 与嵌套条件 | 正/反分支极性正确，不复用描述字符串作为真值 |
| 普通边沿 always / always_ff | 正确识别时序边界，不把普通写法当作组合逻辑 |
| 寄存器 D 在边沿后改变 | 用严格边沿前证据，不把当前 D 判成历史 Q 的来源 |
| 重复写相同值/多拍保持 | 不用 Q 最近变化代替采样事件；检查使能和历史状态 |
| 同步复位/异步事件 | 支持的同步语义正确；未支持异步形式明确停在边界 |
| 反馈寄存器跨周期 | 同信号更早时刻可访问；真正相同状态回访有限停止 |
| 两个时钟相位不同 | clock 模式不静默错配，不宣称周期等价 |
| FSDB 亚 ps 精度/记录合并 | 无法证明边沿顺序时明确不确定 |
| VCD 亚 ps 脉冲/截断末尾同刻组 | 不将取整碰撞当作同刻，不将截断末态作为真实差异 |
| TB 同刻改 D/clock 与非阻塞流水线 | 区分未知调度顺序和可证明的同钟旧值采样 |
| 真实 NPI 动态能力 | mux 极性、复位/使能反馈、正负边沿及有界内部节点展开 |

## 14. 基准与性能结论

在较大实现变更前建立基线，使用本仓库已有工具手工组合的等价调查流程作为参照。两组必须调查相同信号、窗口、层数和证据范围；仅减少检查不能算提速。

至少构造：

1. 直接组合链，检查首次差异与回溯路径。
2. 多层同步流水线，包含使能保持和重复值。
3. 有较多无关扇入的条件逻辑，观察有效分支筛选。
4. 多个节点共享上游的图，检查重复读取和路径复制。
5. 缺失 dump 或截断的负面用例，确认不会以不完整工作获得“更快且正确”的结论。

分别报告冷/热缓存，记录输入规模、波形格式与 timescale、实际后端、预算、运行次数、端到端耗时、中位数及尾部耗时、查询/读取/构建次数、峰值 RSS 和新增缓存峰值。工具内 CPU/IO 与 MCP 传输耗时分开注明。

如果没有测得性能提升，准确报告实际结果。本 PR 的功能价值可以是减少人工接力、改善证据完整性，不需要用未经测量的速度倍数证明。
